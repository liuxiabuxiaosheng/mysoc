# Phase 4 DMA Controller Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add and verify a single-channel BRAM-to-BRAM DMA controller configured through APB and connected to the existing SoC RAM path.

**Architecture:** A focused `dma_controller` owns APB registers and a single-outstanding memory master FSM. `apb_interconnect` and `apb_subsystem` add the DMA window. `soc_top` arbitrates CPU and DMA RAM requests with CPU priority while preserving existing external CPU ports.

**Tech Stack:** SystemVerilog 2012, Icarus Verilog 13.0, VVP, PowerShell.

## Global Constraints

- DMA window is `0x4000_5000–0x4000_5FFF`.
- Registers are `SRC`, `DST`, `LENGTH`, `CTRL`, and RW1C `STATUS`.
- Transfers copy 32-bit words with `4'b1111` strobes and address increments of 4.
- Zero length, unaligned addresses, and start-while-busy set sticky configuration error.
- Memory errors abort the transfer and set sticky bus error.
- Existing phase-one through phase-three tests must continue to pass.
